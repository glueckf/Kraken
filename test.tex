\subsection{\we~Overview}\label{sec:overviewKraken}
 \we's optimization engine consists of two architecturally independent components connected through well-defined interfaces. First, the unified cost evaluation component (C1) integrates \inev~and \prepp, encapsulating their domain-specific cost models.
%
Second, the search component (C2) manages the exploration strategy and navigates the NP-hard solution space using pluggable search algorithms.
 %
Figure~\ref{fig:kraken_architecture} shows an overview of \we's architecture.
%
Given four inputs~\boxaround{1}, i.e., a network topology $\Gamma$, a query
workload $Q$, an event-source function $\phi$, and the set of sink nodes
$N^-$ (typically a single cloud root), \we~derives a decentralized
evaluation plan~\boxaround{12}.
%
In the first step~\boxaround{2}, \we~applies \inev's decomposition to $Q$ under an all-push assumption,
%(justified in Section~\ref{sec:correctness}).
yielding $Q' = (P, \delta)$.
%
In step~\boxaround{3}, all subqueries $p \in P$ are sorted topologically to produce a processing order $\mathcal{O}^P_Q$.
%
This order respects the precedence relation $\delta$, ensuring that every subquery $p_i$ appears only \emph{after} all of its dependencies $\delta(p_i)$. Thus, when placing $p_i$, all its required inputs have already been placed in the current partial plan.
%
Once this order is established, the search component (C2) starts the joint search over placements and communication modes\ariane{, where each partial plan is represented by a state $s$.
%
The state-transition function \texttt{expand}~\boxaround{4} iterates over the subqueries.
%
For the next unplaced subquery $p$ in $\mathcal{O}^P_Q$, \texttt{expand} takes the current state $s$ and generates potential successor states by combining $p$ with candidate nodes for placement.
%
Concretely,} \texttt{expand} identifies a set of candidate nodes $N_{\text{cand}} \subseteq N^f \cup N^-$ for the placement of $p$ and sorts $N_{\text{cand}}$ \ariane{by the availability of required input streams and network distance to their sources.}
%
This sorting \ariane{prioritizes cheap placement and} enables aggressive pruning during evaluation: once a node $n$ violates the latency constraint $\Lambda_{\text{max}}$, all subsequent nodes also violate it and can be discarded.
%
\ariane{Candidates that would exceed per-node compute capacities or the global latency bound are pruned and never enter the candidate pool.}
%
For each remaining candidate node $n$, \texttt{calculate\_cost}~\boxaround{5} is invoked, delegating candidate evaluation to C1.
%
For the pair $(p,n)$, \texttt{calculate\_cost} generates (1) an all-push plan $\pi_{\text{push}}$ and (2) an optimized push-pull plan $\pi_{\text{ppc}}$ computed by \prepp.
%
\ariane{Each of these plans is represented as a \we\ vertex that binds the subquery $p$, the node $n$, and its acquisition sequence.}
%

The unified metric evaluation~\boxaround{7} (Section~\ref{sec:unified_cost_framework}) computes cost and latency metrics for both plans, deriving Ingress (acquisition) and Egress (dissemination) costs using topology-specific distances.
%
\ariane{Each (subquery, node, communication mode) combination thus yields a vertex with associated cost and latency.

For each such vertex, C2 constructs a successor state by extending the current partial plan with this new decision and inserts it into the candidate pool~\boxaround{9}.}

After all candidate states for the current subquery $p$ are normalized and scored, the search strategy~\boxaround{10} (e.g., greedy or beam-$k$ search) selects and \emph{fixes} the placement and communication mode for $p$ based on their objective scores, updates residual capacities, and proceeds to the next subquery in $\mathcal{O}^P_Q$.

Once all subqueries have been placed, \we~outputs the final \we~graph~\boxaround{11}, which specifies for each subquery the node on which it is placed and the acquisition plan describing how it obtains all required inputs.

\subsection{State-Space Model}\label{sec:state-space}
%
We formalize \we's joint optimization as a state-space search, where each state represents a partial or complete decentralized evaluation plan.
%
The basic building block is the \we~vertex, which encodes an atomic decentralization decision.

\paragraph{The \we~Vertex.}
%
A \we vertex \(v\) represents a complete decision for one subquery.
%
We define \(v = (v_p, v_n, v_{\text{steps}})\), where \(v_p \in P\) is a subquery, \(v_n \in N\) is the node on which \(v_p\) is evaluated, and \(v_{\text{steps}} = \langle a_1,\ldots,a_k\rangle\) is the acquisition sequence that \(v_n\) executes to obtain all required inputs for $v_{p}$.
To this end, \we\ builds on the operator placement approach of \inev and extends its vertex model with the PPC acquisition sequence \(v_{\text{steps}}\) from \prepp, yielding a unified vertex representation that binds placement and communication mode.


%
The \we~vertex extends the original \inev~vertex by replacing its abstract forwarding subgraph with the concrete \prepp~acquisition sequence ($v_{\text{steps}}$)~\cite{DBLP:journals/pacmmod/AkiliP023,PushPullSamira}.
%
This substitution atomically binds placement with communication strategy, enabling \we~to evaluate complete decentralization decisions (placement and communication protocol) in a single step rather than sequentially.
%
\paragraph{State Representation and Search Problem.}
%
A state $s$ is a (partial) candidate plan $\pi$, i.e., an \inev~graph~\cite{DBLP:journals/pacmmod/AkiliP023}, that tracks already-made decentralization decisions and which event types and intermediate results are currently available at which nodes.
%
Formally, we define a state as a tuple $s = (\mathcal{V}_s, \mathcal{T}_s)$, where $\mathcal{V}_s: P' \to V$ is the \textit{placement map} from the set of placed subqueries $P' \subseteq P$ to their corresponding \we~vertices $v \in V$, and
%
$\mathcal{T}_s : N \to 2^{\epsilon}$ is the \emph{event availability map}, mapping each node $n \in N$ to the set of event types $\epsilon_n \subseteq \epsilon$ currently available at $n$.
%
\ariane{The map $\mathcal{T}_s$ is updated whenever a subquery $p$ is placed at node $n$, adding its inputs $\mathcal{E}(p)$ and its output as available \emph{event types}, crucial for our state-aware cost function~\ref{sec:unified_cost_framework}}

The solution space $\mathcal{S}$ consists of all states reachable from the empty plan, where no subqueries are placed.
%
The \texttt{expand} function implements the state-transition relation by extending a state $s$ with one or more \we~vertices for the next unplaced subquery in $\mathcal{O}^P_Q$, thereby exploring the joint space of placements and communication strategies.
%
A \emph{goal state} $s^* \in \mathcal{S}$ is any state in which all subqueries $p \in P$ have been placed.
%
The objective of \we~is to find a goal state $s^*$ that minimizes the weighted objective function defined in Section~\ref{sec:unified_cost_framework}.


In sum, our state-space search treats the construction of a complete evaluation plan $\pi$ as a sequence of joint decentralization decisions.
%
By binding \inev~and \prepp~within the \we~vertex, we avoid redundant computation in both decision processes and pass all relevant parameters through a single atomic state (Definition~\ref{def:prepp_plan}).

\subsection{Unified Cost Model}
\label{sec:unified_cost_framework}

We present the Unified Cost  (C1), which forms the analytic core of \we.
This model evaluates a specific placement decision—assigning a subquery $p$ to a node $n$—by modeling the vertex $v = (p, n, v_{\text{steps}})$ as a flow processing unit defined by its \textbf{Ingress} (acquisition of inputs), \textbf{Processing} (computation load), and \textbf{Egress} (dissemination of results).

\we~determines the optimal communication strategy for a vertex via a \emph{dual-strategy evaluation}. For every candidate pair $(p, n)$, it generates two distinct acquisition sequences: an all-push sequence ($v_{\text{steps}}^{\text{push}}$) and an optimized push-pull sequence ($v_{\text{steps}}^{\text{ppc}}$) derived via \prepp~\cite{PushPullSamira}. Both sequences are evaluated under the unified cost model, and the sequence yielding the lower weighted score is selected for the final vertex $v$.

\paragraph{Vertex Metrics.}
The vertex cost $C_v$ sums the transmission overhead of the chosen acquisition sequence and the sink forwarding. The vertex latency $L_v$ is defined recursively to capture the critical path, including local processing $\ell^p_v$ and transmission delays:
\begin{equation}\label{eq:vertex_cost}
    C_v = \underbrace{C_{\text{acq}}(v_{\text{steps}}, n, s)}_{\text{Ingress}} + \underbrace{C_{\text{diss}}(p, n)}_{\text{Egress}}
\end{equation}
\begin{equation}\label{eq:vertex_latency}
    L_v = \xi \cdot \ell^p_v + \underbrace{\left(\ell^t_{\text{acq}}(v_{\text{steps}}, n, s) + \ell^t_{\text{diss}}(p, n)\right)}_{\ell^t_v} + \max_{u \in \delta(p)} L_u
\end{equation}
Here, $\xi \in \{0,1\}$ allows weighting of processing latency (set to $\xi=0$ for transmission-dominant optimization).

\paragraph{Ingress: Locality-Aware Acquisition.}
Ingress metrics quantify the cost of the acquisition steps $v_{\text{steps}}$ required to retrieve input events.
A key contribution of this model is the rigorous handling of \emph{fragmented physical streams} via topology-aware locality.
To evaluate a logical stream $S$ at node $n$, the system must acquire all its physical fragments. However, if $S$ has been reassembled at $n$ by a prior subquery (i.e., $S \in \mathcal{T}_s(n)$), no transmission is required.

We define the \textbf{Remote Source Set} $\Phi_{\text{remote}}$ as the set of physical nodes that must transmit data to $n$. This set filters the global source mapping $\phi(S)$ against the local state $\mathcal{T}_s(n)$ and the node's own identity:
\begin{equation}\label{eq:remote_source_set}
    \Phi_{\text{remote}}(a_i, n, s) = \bigcup_{S \in \rho_i}
    \begin{cases}
        \emptyset & \text{if } S \in \mathcal{T}_s(n)\\
        \phi(S) \setminus \{n\} & \text{otherwise}
    \end{cases}
\end{equation}
If $S$ is already reassembled locally ($S \in \mathcal{T}_s$), the set is empty (cost is zero). If $S$ is scattered, we must fetch from all sources $\phi(S)$ except $n$ itself (partial locality).

\paragraph{Acquisition Cost ($C_{\text{acq}}$).}
The acquisition cost aggregates the communication overhead for all steps in the sequence. We decompose the cost of a single step $a_i = (\Psi_i, \rho_i)$ into a \emph{Request} component (broadcasting predicates) and a \emph{Response} component (transmitting filtered events):
\begin{equation}
    C_{\text{acq}}(v_{\text{steps}}, n, s) = \sum_{a_i \in v_{\text{steps}}} \left( C_{\text{req}}(a_i) + C_{\text{res}}(a_i) \right)
\end{equation}

The \textbf{Request Cost} captures the transmission of predicate tuples from the logical streams in $\Psi_i$ to all relevant remote sources. Crucially, we scale the volume of these predicates by their \emph{current selectivity} $\sigma(\Psi_i)$ to account for prior filtering in the acquisition chain:
\begin{equation}
    C_{\text{req}}(a_i) = \sum_{S \in \Psi_i} R(S) \cdot \sigma(\Psi_i) \sum_{n^+ \in \Phi_{\text{remote}}} \dist(n, n^+)
\end{equation}
Here, $\sigma(\Psi_i)$ represents the cumulative selectivity of the streams in $\Psi_i$ based on the steps executed so far. If $\Psi_i = \emptyset$ (all-push), the request cost is 0.

The \textbf{Response Cost} accounts for the transmission of the filtered physical streams from their specific source nodes back to $n$:
\begin{equation}
    C_{\text{res}}(a_i) = \sum_{S \in \rho_i} \sum_{n^+ \in \Phi_{\text{remote}} \cap \phi(S)} r(n^+, S) \cdot \sigma_i \cdot \dist(n^+, n)
\end{equation}
Here, $\sigma_i = \sigma(S \cup \Psi_i)$ denotes the joint selectivity of the stream $S$ and the pull predicate.
The \textbf{Acquisition Latency} $\ell^t_{\text{acq}}$ is the round-trip time to the furthest source node in $\Phi_{\text{remote}}$:
\begin{equation}
    \ell^t_{\text{acq}}(v_{\text{steps}}, n, s) = \sum_{a_i \in v_{\text{steps}}} \left(
        \max_{n^+ \in \Phi_{\text{remote}}} \dist(n, n^+) + \max_{n^+ \in \Phi_{\text{remote}}} \dist(n^+, n)
    \right)
\end{equation}

\paragraph{Egress: Sink-Aware Dissemination.}
Egress metrics account for delivering the result of a root projection $p \in Q$ to the system sinks $N^-$.
Standard placement algorithms often assume the evaluation node is the final destination. In hierarchical fog-cloud topologies, however, placing a high-fan-out query in the fog is only beneficial if the cost of forwarding results to the cloud does not negate the savings.
\we\ explicitly models this dissemination cost:
\begin{equation}
    C_{\text{diss}}(p, n) =
    \begin{cases}
        r^{\text{out}}(p) \cdot \sum_{n^- \in N^-} \dist(n, n^-) & \text{if } p \in Q \wedge n \notin N^- \\
        0 & \text{otherwise}
    \end{cases}
\end{equation}
Similarly, the dissemination latency $\ell^t_{\text{diss}}(p, n)$ is the time required to reach the furthest sink.

\paragraph{State Aggregation and Scoring.}
The search algorithm explores the solution space by iteratively extending a partial plan $s_{\text{base}}$ with a new vertex $v$.
The successor state $s_{\text{next}}$ aggregates the metrics by summing the transmission costs, $C(s_{\text{next}}) = C(s_{\text{base}}) + C_v$, and re-evaluating the end-to-end latency as the critical path among all placed projections $P'$, i.e., $L(s_{\text{next}}) = \max_{p \in P'} L_{v(p)}$.

To guide the search, \we\ ranks candidate states in the pool $S_{\text{cand}}$ using a multi-objective scoring function $F(s)$. We normalize costs and latencies relative to the current candidate pool bounds to ensure dimensional consistency:
\begin{equation}\label{eq:scoring_function}
    F(s) = \alpha \cdot \frac{C_s - C_{\min}}{C_{\max} - C_{\min}} + (1-\alpha) \cdot \frac{L_s - L_{\min}}{L_{\max} - L_{\min}}
\end{equation}
This function allows the planner to dynamically trade off bandwidth conservation ($\alpha \to 1$) against real-time responsiveness ($\alpha \to 0$) based on application requirements.

\paragraph{Summary.}
In sum, \we's dual-strategy evaluation uses a unified topology-aware cost model to assess each placement $(p,n)$ under both the all-push strategy $v_{\text{steps}}^{\text{push}}$ and the predicate-based push–pull strategy $v_{steps}^{\text{ppc}}$. This allows \we~to select configurations that may look suboptimal under all-push alone but become superior once communication is optimized. Our cost model adapts the state-of-the-art formulations of \inev~and \prepp~to fog–cloud constraints by (i) generalizing \prepp's local-event subtraction from centralized queries to intermediate subqueries, thereby exploiting event reuse and eliminating redundant transmissions when event types are co-located, and (ii) adding an explicit sink-cost term that accounts for forwarding final outputs from in-network nodes to fixed cloud sinks, correcting the systematic underestimation of communication costs in \inev.

Focusing on transmission cost and transmission latency as potentially conflicting objectives, \we~employs a multi-objective scoring function $F(s)$ that exposes a tunable trade-off between them~\cite{cugola2013deployment,akdere2008plan}. This enables deployments to prioritize low transmission cost, low latency, or a balanced compromise, while extending \inev\ with predicate-based PPC via \prepp~\cite{DBLP:journals/pacmmod/AkiliP023,PushPullSamira}.

\subsection{Search Component}\label{sec:search}
%
\we's search component (C2) decouples decentralized decision-making from traversal of the solution space, allowing us to apply generic search algorithms.
%
C2 treats planning as a search over states $s \in \mathcal{S}$ using three domain-specific primitives: the state transition function \texttt{expand}, the objective function $F(s)$ (Equation~\ref{eq:scoring_function}), and the \texttt{is\_goal} predicate.
%
On top of this interface, we implement two strategies that trade solution quality for computational efficiency: greedy search and beam-$k$ search.

\textit{Greedy search}
%
implements a simple best-first strategy, commonly applied to both NP-hard decision problems~\cite{PushPullSamira,DBLP:journals/pacmmod/AkiliP023}.
%
In our state-space search, it maintains a single current state $s$.
%
In each step, it calls \texttt{expand}$(s)$, evaluates all successors using $F(s)$, and selects the lowest-scoring successor as the new current state.
%
This process repeats until a goal state is reached.
%
Greedy search is computationally efficient and memory-light, but may converge to a locally optimal solution.

\textit{Beam-$k$ search} improves solution quality by maintaining the best $k$ candidate solutions (the \emph{beam}). It initializes the beam $B$ with the start state $s_0$.
%
In each iteration, it expands all states in $B$, collects all valid successors into a candidate pool $C$, ranks $C$ globally using $F(s)$, and selects the top $k$ candidates to form the new beam for the next iteration.
%
When goal states are reached, the algorithm returns the candidate with the best objective score $F(s)$.
%
Setting $k=1$ reduces the beam to a greedy search.
%
Larger $k$ values explore more of the solution space, increasing the probability of finding a globally superior solution at the cost of roughly $k$-times greater computational overhead.

\paragraph{Extensibility}
The decoupled design turns the CEP-specific placement problem into a generic combinatorial search problem.
%
All domain logic is encapsulated in \texttt{expand}, $F(s)$, and \texttt{is\_goal}. Thus, the search component itself is agnostic to operator semantics, push-pull details, or network topology.
%
This abstraction (i) allows \we~to trade optimality for speed by switching between greedy, or beam-$k$, and (ii) enables the future integration of more advanced search techniques, such as A* search~\cite{DBLP:journals/pvldb/NtouniBG25} (by defining an admissible heuristic) or branch-and-bound, without modifying the unified cost evaluation framework or the underlying state-space model.
